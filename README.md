# MAX-бот «картинка → выжимка → рассылка»

Бот для мессенджера MAX. Владелец присылает изображение, нейросеть через OpenRouter делает из него краткую выжимку по заданному промпту, результат попадает в архив и рассылается получателям. Получатели подключаются по персональным одноразовым ссылкам-приглашениям.

> **Статус.** Бот проверен на поддельном HTTP (заглушка `httpx`). Живой MAX и живой OpenRouter не проверялись. Подробности в разделе [Что проверено и что нет](#что-проверено-и-что-нет).

## Требования и установка

Нужен Python 3.9 или новее и пакет `httpx`. На Windows также нужен `tzdata`, иначе часовой пояс `Europe/Moscow` не найдётся.

**Windows (PowerShell), из папки `max_bot`:**

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install httpx tzdata
copy .env.example .env
notepad .env            # впишите значения обязательных переменных
python run_bot.py
```

Если PowerShell не даёт активировать окружение, выполните один раз `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` или запускайте напрямую `.\.venv\Scripts\python.exe run_bot.py`.

**Linux и macOS, из папки `max_bot`:**

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install httpx
cp .env.example .env
chmod 600 .env          # файл с секретами читает только владелец
nano .env
python run_bot.py
```

Если обязательной переменной нет, бот печатает «ОШИБКА НАСТРОЙКИ: Не заданы обязательные переменные: …» и завершается с кодом 2.

## Переменные .env

Файл читается рядом с `run_bot.py`. Строки вида `ИМЯ=значение`, без пробелов вокруг `=`. Если переменная задана и в файле, и в окружении Windows, **окружение важнее**.

| Переменная | Обязательная | По умолчанию | Назначение |
|---|---|---|---|
| `MAX_BOT_TOKEN` | да | нет | токен бота в MAX; секрет, в логах маскируется |
| `OWNER_ID` | да | нет | числовой user_id владельца в MAX |
| `OPENROUTER_API_KEY` | да | нет | ключ OpenRouter (начинается с `sk-or-`); секрет, маскируется |
| `OPENROUTER_MODEL` | да | нет | модель OpenRouter вида `производитель/модель`; нужна модель с поддержкой изображений |
| `MAX_BOT_NAME` | рекомендуется | пусто | имя бота без `@`; без него ссылки-приглашения не создаются |
| `INVITE_TTL_HOURS` | нет | `72` | срок действия ссылки-приглашения, часов (1…720) |
| `DB_PATH` | нет | `max_bot.sqlite3` в папке бота | файл базы SQLite |
| `SAVE_DIR` | нет | `incoming_images` в папке бота | папка для картинок |
| `MAX_IMAGE_BYTES` | нет | `10485760` (10 МБ) | максимальный размер картинки |
| `ARCHIVE_DAYS` | нет | `30` | срок хранения архива и картинок, дней (1…36500) |
| `BUTTON_TTL_HOURS` | нет | `24` | срок действия кнопок «Текст» и «Картинка», часов (1…720) |
| `BOT_TZ` | нет | `Europe/Moscow` | часовой пояс дат |
| `MAX_UNSUBSCRIBE_WEBHOOK` | нет | `0` | `1`: при старте снять подписку webhook (после этого webhook перестанет работать) |
| `LOG_LEVEL` | нет | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` |
| `LOG_DIR` | нет | `logs` в папке бота | папка журналов |
| `LOG_KEEP_RUNS` | нет | `10` | сколько последних запусков хранить в `LOG_DIR` |
| `OPENROUTER_REFERER` | нет | `http://localhost` | заголовок `HTTP-Referer` для OpenRouter |
| `OPENROUTER_TITLE` | нет | `MAX Image Bot` | заголовок `X-Title` для OpenRouter |
| `POLL_TIMEOUT` | нет | `30` | таймаут долгого опроса MAX, секунд (0…90) |
| `POLL_LIMIT` | нет | `100` | максимум обновлений за один запрос (1…1000) |

Неверное значение (например, `ARCHIVE_DAYS=abc`) даёт понятное сообщение об ошибке настройки при старте.

**Как узнать свой user_id.** Впишите временно `OWNER_ID=1`, запустите бота и напишите ему с нужного аккаунта MAX. В журнале появится строка `чужой отправитель user_id=…`: это ваш номер. Остановите бота (Ctrl+C), впишите номер в `OWNER_ID` и запустите снова.

## Первый запуск и мастер настройки

Пока настройка не завершена, картинки не обрабатываются. Мастер запускается от первого сообщения владельца:

1. **Промпт.** Ответьте «да», чтобы принять стандартный (его можно посмотреть командой `/prompt`), или пришлите свой текст и подтвердите его словом «да».
2. **Получатели.** Пришлите одно или несколько имён, каждое с новой строки. Для каждого бот покажет жирным порядковый номер и имя, а на следующей строке — персональную ссылку. Можно добавлять имена несколькими сообщениями; закончив, напишите «готово».
3. **Проверка.** Ответьте «да», чтобы завершить настройку.

## Команды владельца

Порядок обработки сообщения владельца: сначала ожидающее подтверждение («да» выполняет действие, любой другой ответ отменяет его), затем команды (текст с «/»), затем мастер, затем картинка. Если картинки нет, бот отвечает «Нужно прислать изображение».

| Команда | Что делает |
|---|---|
| `/help` | список команд |
| `/recipients` | список получателей и их статус (активен или отключён) |
| `/add Имя` | создать персональные ссылки-приглашения (одно или несколько имён, каждое с новой строки); имя и номер жирным, ссылка следующей строкой |
| `/links` | статусы ссылок: ожидает (с датой окончания), ждёт подтверждения имени (с ID), подключён (с ID), отозвана, истекла |
| `/newlink Имя` | перевыпустить приглашения для одного или нескольких имён (старые ссылки перестают работать); имя и номер жирным, ссылка следующей строкой |
| `/revoke Имя` | отозвать одно или несколько неиспользованных приглашений; несколько имён — каждое с новой строки |
| `/remove Имя или ID` | удалить одного или нескольких подключённых получателей (подтверждается «да»); имена/ID — каждое с новой строки. Для ещё не подключившихся используется `/revoke` |
| `/pause Имя или ID` | временно не слать рассылку получателю; запись остаётся |
| `/resume Имя или ID` | снова слать рассылку получателю |
| `/archive [N]` | последние N записей архива, по умолчанию 10 |
| `/archive find слово или дата` | поиск в архиве по слову или дате `ДД.ММ.ГГГГ` / `ГГГГ-ММ-ДД` |
| `/resend номер получатель или все [текст|картинка]` | продолжить выбранную рассылку только для недоставленных адресатов; несколько имён/ID — каждое с новой строки. Если выбранный адресат уже получил материал, бот сообщает об этом и не создаёт дубликат. Если формат ещё не выбран, укажите его явно |
| `/prompt` | показать текущий промпт |
| `/prompt set текст` | заменить промпт (подтверждается «да»; действует для следующих картинок) |
| `/status` | число получателей, число записей архива, последний результат и модель |

## Получатели и приглашения

- Ссылка имеет вид `https://max.ru/<MAX_BOT_NAME>?start=…`. Без `MAX_BOT_NAME` ссылка не создаётся, владельцу приходит напоминание вписать имя в `.env`.
- Токен в ссылке показывается владельцу **один раз**. Повторно его можно получить только перевыпуском (`/newlink`). Команды `/links`, `/recipients`, `/status` токен не показывают.
- Ссылка одноразовая и действует `INVITE_TTL_HOURS` часов. Получатель открывает её, нажимает Start и подтверждает своё имя словом «да».
- Чужой человек, который открыл ссылку с неверным или уже использованным токеном, получает отказ. Владельцу приходит служебное сообщение. Больше 5 попыток в час с одного аккаунта: ответ временно не отправляется, владелец предупреждается.
- Получатель, который уже подключён, может написать боту: «повтори последнее», «повтори [номер]», «повтори по теме [слово]», «повтори за [дата ДД.ММ.ГГГГ]». Ему доступны только записи, которые ему уже доставлены. Другие сообщения получают подсказку с этими командами.
- Незнакомый человек, который написал боту без приглашения, получает ответ «только по приглашению», а владельцу приходит уведомление с его ID и именем.

## Как обрабатывается картинка

1. Владелец присылает картинку. Бот проверяет формат по первым байтам файла (JPEG, PNG, WebP) и размер (`MAX_IMAGE_BYTES`).
2. Картинка сохраняется в `SAVE_DIR`, и запись появляется в архиве.
3. Нейросеть получает промпт и картинку. Запросы идут **строго по одному**: если пришли несколько картинок, они обрабатываются по очереди.
4. Результат записывается в архив. Владелец выбирает кнопкой «Текст» или «Картинка» ровно один формат рассылки для этой записи. После выбора формат закрепляется: переключить эту запись на другой формат нельзя. Кнопки действуют `BUTTON_TTL_HOURS` часов (по умолчанию 24).
5. **Главное правило рассылки: для одного материала разрешён только один формат; выбранную рассылку можно повторять до успешной доставки всем получателям.** Повторное нажатие той же кнопки продолжает отправку только получателям без подтверждённой успешной доставки; уже получившие материал пропускаются. Выбрать другой формат для этой записи нельзя. Для записей, которые были разосланы старой версией бота до сохранения выбранного формата, автоматический повтор заблокирован: прежняя база не позволяет безопасно определить отправленный формат.
6. Если загрузка картинки не удалась, отдельные доставки не отмечаются как неуспешные: можно повторить ту же кнопку или выполнить `/resend`.
7. Владельцу приходит итог: сколько доставлено из скольких и кому не удалось. Команда /resend номер все повторяет рассылку для активных получателей организации, сохранённой в записи; /resend номер имя или ID — адресно для одного получателя или списка (каждое имя/ID с новой строки). Если выбранный адресат уже получил материал, бот сообщает об этом; подтверждённые доставки повторно не отправляются. Если формат ещё не выбран, обязательно добавьте текст или картинка, например /resend 5 все картинка.

Отправка одному получателю идёт не чаще двух раз в секунду. Ошибка доставки повторяется до 5 раз; если попытки исчерпаны, в журнале и владельцу указывается получатель.

## Нейросеть и ошибки

Запрос идёт в OpenRouter (`/api/v1/chat/completions`), таймаут 60 секунд.

- **429, 408, 5xx, сетевые ошибки, таймаут и пустой ответ** повторяются с паузами **2, 3, 5 и 8 секунд**: всего пять попыток. Если все попытки неудачны, владелец получает сообщение «Нейросеть отвечает 429 (слишком много запросов): пять попыток не помогли. Картинку можно прислать позже» (или аналогичное для другой ошибки), а причина пишется в журнал.
- **402 (недостаточно кредитов)** не повторяется. Владелец получает отдельное сообщение о том, что нужно пополнить баланс OpenRouter.
- **401 и 403** означают, что ключ не принят или доступ запрещён: проверьте `OPENROUTER_API_KEY`. **404** означает, что модель не найдена: проверьте `OPENROUTER_MODEL`. Эти ошибки не повторяются.
- При старте бот проверяет каталог моделей OpenRouter и предупреждает, если выбранная модель не заявляет поддержку изображений. Сам запуск эта проверка не блокирует.

## Архив, журнал и хранение данных

**Архив.** Каждый результат сохраняется: дата, заголовок, текст, путь к картинке, статус. Записи и картинки старше `ARCHIVE_DAYS` дней удаляются при запуске бота. Для резервной копии остановите бота и скопируйте файл базы и папку `incoming_images`.

**Журнал.** Бот пишет одновременно на экран и в файл `logs/bot_ГГГГММДД_ЧЧММСС.log`. Хранятся последние `LOG_KEEP_RUNS` запусков, старые файлы удаляются. Секреты (токен, ключ OpenRouter) маскируются в каждой строке журнала. При старте в журнал пишется путь к файлу журнала.

**Остановка.** Ctrl+C останавливает опрос. Задачи в работе доделываются до 30 секунд; оставшиеся отменяются, но остаются во входящей очереди и повторятся при следующем запуске.

**Опрос и защита от потери событий.** Бот получает обновления через long polling (`GET /updates`). Пачка обновлений и новый marker записываются в базу одной операцией, и только потом обрабатываются. Если бот упадёт посреди обработки, необработанные события обработаются при следующем запуске, дубли отсекаются по `mid`. Ошибки обработки callback-кнопок повторяются до пяти раз с увеличивающейся задержкой; попытки и следующая дата повтора хранятся в `inbox`.

**Webhook.** Пока у бота есть подписка webhook, long polling событий не получает. Если при старте обнаружена подписка и `MAX_UNSUBSCRIBE_WEBHOOK=0`, бот останавливается и объясняет, что делать. При `MAX_UNSUBSCRIBE_WEBHOOK=1` он сам снимает подписку.

## Структура кода

Код разбит на модули пакета `maxbot`. Ниже порядок, в котором модули зависят друг от друга: каждый использует только модули выше себя.

| Модуль | Что внутри |
|---|---|
| `base.py` | настройки из `.env`, журнал, общие функции текста и времени, константы |
| `storage.py` | база SQLite: настройки, очередь, архив, входящие обновления, состояние рассылок и доставки каждому получателю |
| `transport.py` | отправка сообщений MAX с паузами и повторами, оповещение владельца |
| `max_api.py` | работа с API MAX: опрос обновлений, разбор сообщений, загрузка картинок |
| `ai.py` | клиент OpenRouter: запрос, повторы, сообщения об ошибках нейросети |
| `people.py` | получатели, приглашения, доставка и повтор рассылок с закреплённым форматом |
| `owner.py` | команды владельца, мастер настройки, обработка картинок |
| `bot.py` | главный цикл: опрос, фоновые задачи, повторы ошибок callback, запуск и остановка |

`run_bot.py` только вызывает `maxbot.bot.main`. Если вы меняете код, запускайте бота из папки `max_bot`, иначе Python не найдёт пакет `maxbot`.

## Что проверено и что нет

**Проверено на поддельном HTTP (заглушка `httpx`):**

- 29 проверок модулей: опрос и сохранение marker, повторы нейросети (429 с паузами 2, 3, 5, 8 с, ошибка 400 без повтора, ограничение очереди до одного запроса), приглашения и их ограничения, команды владельца, кириллица в поиске и сравнении имён, токен показывается один раз, отсутствие `MAX_BOT_NAME`, очистка входящей очереди.
- 7 дымовых проверок: запуск, опрос, ошибки 401 и 500, webhook, восстановление очереди, запуск и остановка, отказ без переменных окружения.
- Статическая проверка: все 130 определений на месте, нет циклов импорта и неиспользуемых импортов, каждый модуль импортируется отдельно.
- Пять прогонов подряд с разными значениями `PYTHONHASHSEED`: без изменений результата.

Тесты в эту папку не входят.

**Не проверено:**

- Живой MAX: реальные ответы `GET /updates`, подписки, отправка сообщений, скачивание картинок.
- Живой OpenRouter: реальные ответы, заголовки лимитов, работа выбранной модели с картинками. Формат запроса (`chat/completions`) не подтверждён на живом сервисе.
- Запуск на вашем компьютере: этот README написан по коду; запуск `python run_bot.py` на Windows нужно проверить самостоятельно.
- Ctrl+C на Windows, запуск как службы, работа через прокси, нагрузка и длительная работа.
- Сравнение с реальными `httpx` (в проверках использовалась заглушка).


## Разделение получателей по организациям

У каждого получателя, приглашения и архивного материала хранится код организации — битовая маска:

- 1 — Озон;
- 2 — WB;
- 3 — обе организации (значение по умолчанию).

В командах /add и /newlink код указывается после имени через пробел. Каждое имя — на отдельной строке. Например:

    /add
    Иванов 1
    Петров 2
    Сидорова 3
    Кузнецов

Если код не указан, назначаются обе организации. Если последним фрагментом имени указано другое число (например, «Аня 5»), оно остаётся частью имени, назначаются обе организации, а отчёт предупреждает о возможной опечатке. В отчёте создания ссылок показывается назначенная организация. Код переносится из приглашения в карточку получателя после ответа «да». Команда /recipients показывает назначенную организацию рядом с именем.

Текст/подпись, приложенный к изображению, задаёт организацию-цель для материала:

- 1 или «озон» — только Озон;
- 2, «wb» или «вб» — только WB;
- 3 или «все» — обе организации;
- пустая или другая подпись — обе организации по умолчанию.

Если подпись непустая, но не распознана, бот предупредит владельца и продолжит обработку с целью «обе организации». Пустая подпись считается штатным значением по умолчанию.

Выбранная цель сохраняется в записи архива. Первичная рассылка по кнопке и команда /resend номер все используют эту сохранённую цель: активные получатели выбираются по пересечению битовых масок. Адресный /resend номер имя или ID не фильтруется по организации и позволяет повторить доставку конкретному получателю.
