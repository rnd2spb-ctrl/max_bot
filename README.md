# MAX-бот «картинка → выжимка → рассылка» (long polling, версия 2)

Бот для мессенджера MAX. Владелец присылает изображение, нейросеть через OpenRouter делает из него краткую выжимку по заданному промпту, результат попадает в архив и рассылается получателям. Скрипт один файл: `max_polling_bot.py`. Настройки лежат в `.env` рядом с ним.

> **Статус.** Скрипт проверен только на поддельном HTTP (`httpx.MockTransport`). Живой MAX и живой OpenRouter не проверялись. Подробности в разделе [Что проверено и что нет](#что-проверено-и-что-нет).

## Состав и требования

| Файл | Назначение |
|---|---|
| `max_polling_bot.py` | сам бот (один файл, 14 разделов с комментариями) |
| `.env` | настройки; лежит рядом со скриптом, в git не добавляется |
| `max_bot.sqlite3` | база SQLite, создаётся при первом запуске |
| `incoming_images/` | сохранённые картинки, создаётся при первом запуске |

Требования: Python 3.9 или новее (нужен модуль `zoneinfo`; сам скрипт проверялся на Python 3.12) и пакет `httpx` версии от 0.27 до 1.0. На Windows дополнительно нужен `tzdata`, иначе часовой пояс `Europe/Moscow` не найдётся.

Отдельного файла `requirements.txt` в этом шаге нет. Список зависимостей (`httpx>=0.27,<1.0` и `tzdata; sys_platform == "win32"`) указан в командах ниже.

## Быстрый старт

### Linux и macOS

```bash
mkdir -p ~/max-bot && cd ~/max-bot
# положите сюда max_polling_bot.py и .env
python3 -m venv .venv
source .venv/bin/activate
pip install "httpx>=0.27,<1.0"
chmod 600 .env          # файл с секретами читает только владелец
nano .env               # впишите значения (таблица ниже)
python max_polling_bot.py
```

### Windows (PowerShell)

```powershell
mkdir C:\max-bot ; cd C:\max-bot
# положите сюда max_polling_bot.py и .env
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install "httpx>=0.27,<1.0" tzdata
notepad .env            # впишите значения (таблица ниже)
python max_polling_bot.py
```

Если PowerShell не даёт активировать окружение, выполните один раз `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` либо запускайте напрямую `.\.venv\Scripts\python.exe max_polling_bot.py`.

### Заполнение .env

Если у вас есть готовый `.env` из шага 2, просто скопируйте его рядом со скриптом. Если нет, создайте файл с таким минимумом (значения подставьте свои):

```ini
MAX_BOT_TOKEN=токен_бота_MAX
OWNER_ID=123456789
OPENROUTER_API_KEY=ваш_новый_ключ_OpenRouter
OPENROUTER_MODEL=производитель/модель_с_поддержкой_изображений
```

Правила разбора файла: строки `ИМЯ=значение` без пробелов вокруг `=`; допустимы `export ИМЯ=...`, значения в одинарных и двойных кавычках, комментарии `#` (в значении без кавычек комментарий начинается с пробела и `#`), BOM и переводы строк Windows. Если файла нет, берутся переменные окружения. Если переменная задана и там и там, **окружение приоритетнее файла**.

Если обязательной переменной нет, скрипт печатает «ОШИБКА НАСТРОЙКИ: Не заданы обязательные переменные: …» и завершается с кодом 2.

## Как узнать свой user_id

Номер нужен для `OWNER_ID`. Бот сам напишет его в лог:

1. Временно впишите любое число, например `OWNER_ID=1`, остальные обязательные переменные заполните.
2. Запустите скрипт, откройте бота в MAX, нажмите Start и напишите любое сообщение.
3. В логе появятся строки `bot_started: user_id=…` и `чужой отправитель user_id=…`. Это и есть ваш номер. (Побочный эффект: бот ответит вам «Этот бот работает только по приглашению», пока ваш номер не стал владельцем.)
4. Остановите скрипт (Ctrl+C), впишите настоящий номер в `OWNER_ID` и запустите снова.

Так же получают номера получателей: пусть человек нажмёт Start у бота, и его user_id появится в логе.

## Первоначальная настройка и команды

### Мастер настройки

Пока настройка не завершена, изображения не обрабатываются. Мастер запускается сам от первого сообщения владельца и ведёт по шагам:

1. **Промпт.** Ответьте «да», чтобы принять стандартный (посмотреть его можно командой `/prompt`), или пришлите свой текст и подтвердите его словом «да».
2. **Получатели.** Присылайте по одному в формате «имя ID», например `Анна 201`. Закончив, напишите «готово».
3. **Проверка.** Бот покажет промпт и список получателей, ответьте «да».

Каждый получатель должен сам открыть бота и нажать Start, иначе сообщения ему не дойдут.

### Порядок обработки сообщения владельца

1. Если ждёт подтверждения действие (удаление, замена промпта, повторная отправка): «да» выполняет его, любой другой ответ отменяет («Отменено.»).
2. Если текст начинается с «/», это команда (даже если приложена картинка).
3. Если настройка не завершена, идёт мастер.
4. Если приложено изображение, оно обрабатывается.
5. Иначе бот отвечает «Нужно прислать изображение».

### Команды владельца

| Команда | Что делает |
|---|---|
| `/recipients` | список получателей |
| `/add [имя] [ID]` | добавить получателя |
| `/remove [имя или ID]` | удалить получателя (после подтверждения «да») |
| `/pause [имя или ID]` | временно отключить получателя: рассылки ему не приходят, запись в базе остаётся |
| `/resume [имя или ID]` | снова включить получателя: рассылки возобновляются |
| `/archive [N]` | последние N записей (по умолчанию 10) |
| `/archive find [слово или дата]` | поиск в архиве по слову (в заголовке и тексте) или дате `ДД.ММ.ГГГГ` / `ГГГГ-ММ-ДД` |
| `/resend [номер] [получатель или все]` | повторная отправка записи архива (после подтверждения «да») |
| `/prompt` | показать текущий промпт |
| `/prompt set [текст]` | заменить промпт (после подтверждения «да») |
| `/status` | число получателей, записей, последний результат, модель, последние лимиты OpenRouter |
| `/help` | список команд |

### Что получают получатели

Рассылка начинается строкой «Результат от [дата и время]:» и текстом выжимки. Тексты длиннее 4000 символов уходят частями с пометками «(1/N)». Владельцу приходит итог: **«Отправлено: N из M. Не доставлено: [имена].»**

Получатель может написать боту: «повтори последнее», «повтори [номер]», «повтори по теме [слово]», «повтори за [дата ДД.ММ.ГГГГ]». Ему доступны только записи, которые ему уже были доставлены.

## Как работает бот

**Long polling.** Бот в бесконечном цикле вызывает `GET https://platform-api2.max.ru/updates` с параметрами `limit`, `timeout`, `marker` и `types` (`message_created`, `bot_started`), заголовок `Authorization` содержит токен. Сервер держит запрос открытым до `POLL_TIMEOUT` секунд и отвечает, как только появляются события.

**Marker и защита от пропуска событий.** Ответ содержит `marker`, его надо передавать в следующем запросе. Полученная пачка обновлений и новый marker записываются в SQLite **одной транзакцией** (таблица `inbox`), и только потом запускается обработка. Если процесс упадёт после записи, при следующем старте необработанные события берутся из `inbox` и обрабатываются заново; если до записи, marker не сдвинут, и MAX отдаст события снова. Дубликаты отсекаются по `mid` сообщения. Marker, который «уменьшился», игнорируется.

**Фоновая обработка.** Каждое обновление обрабатывается отдельной задачей, поэтому медленная нейросеть не блокирует опрос. Тексты и настройка владельца идут строго по очереди.

**Паузы и ошибки.** При ошибках сети, HTTP 429 и 5xx пауза растёт 1, 2, 4 … до 60 секунд с небольшим разбросом, `Retry-After` сервера учитывается. При HTTP 401 бот останавливается с сообщением, что токен неверен или отозван: повторять бессмысленно.

**Проверка и снятие webhook.** Пока у бота есть подписка webhook, `GET /updates` событий не отдаёт. При старте бот вызывает `GET /subscriptions`:

- подписок нет: работает дальше;
- подписка есть и `MAX_UNSUBSCRIBE_WEBHOOK=0`: останавливается и объясняет, что делать (автоотписка по умолчанию выключена, чтобы случайно не отключить рабочий webhook);
- подписка есть и `MAX_UNSUBSCRIBE_WEBHOOK=1`: вызывает `DELETE /subscriptions` для каждой подписки. После этого webhook перестаёт работать.

**Остановка.** Ctrl+C и SIGTERM останавливают опрос; задачи в работе дорабатывают до 30 секунд, остальные отменяются и остаются во входящей очереди для повтора при следующем запуске.

**Отправка сообщений.** В один чат уходит не более 2 сообщений в секунду (это внутреннее правило бота, не требование документации). При 429 и 5xx отправка повторяется до 5 раз. Ответ 4xx (кроме 429) считается отказом; если от получателя ещё не было Start или сообщения, в журнале пишется «не запустил бота».

## Клиент OpenRouter и ограничения

**Запрос.** `POST https://openrouter.ai/api/v1/chat/completions`, заголовки `Authorization: Bearer <ключ>`, `Content-Type: application/json`, `HTTP-Referer` и `X-Title`, таймаут 60 секунд. Модель берётся из `OPENROUTER_MODEL`. Картинка передаётся как часть `image_url` с base64 data-URL, текст промпта идёт первым:

```json
{
  "model": "<OPENROUTER_MODEL>",
  "messages": [{
    "role": "user",
    "content": [
      {"type": "text", "text": "<промпт>"},
      {"type": "image_url", "image_url": {"url": "data:image/png;base64,..."}}
    ]
  }]
}
```

**Формат запроса: подтверждён с оговоркой.** Структура (эндпоинт chat/completions, массив частей с текстом первым, `image_url.url` как base64 data-URL, типы PNG/JPEG/WebP/GIF) подтверждена руководством OpenRouter «How to Send an Image to an LLM via API» от 14.08.2026. Оговорка: страница документации «Image Inputs» на 16.11.2026 описывает тот же сценарий через другой интерфейс, Responses API (`/api/v1/responses`, часть `input_image`). Бот использует `/chat/completions`, как в вашем образце `limit_openrouter.py`. Реальный запрос с вашим ключом и моделью не выполнялся.

**Модель.** В образце `limit_openrouter.py` была модель `nemotron-3.5-lightning:free`. Подходит ли она для картинок, не проверялось. Для распознавания нужна модель, у которой во входных модальностях есть `image` (каталог: <https://openrouter.ai/models>). Если модель текстовая, OpenRouter вернёт ошибку, а бот ответит «Не удалось распознать изображение, пришлите ещё раз». При старте бот сверяется с каталогом моделей и пишет предупреждение, если выбранная модель не заявляет поддержку изображений; запуск проверка не блокирует.

**Лимиты.** Бот разбирает заголовки `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`, `Retry-After` и такие же значения из `error.metadata.headers` тела ошибки (заголовок главнее). `X-RateLimit-Reset` может быть в миллисекундах или секундах: если число больше 1 000 000 000 000, оно делится на 1000. Время сброса выводится в UTC и по Москве вместе с оставшимся временем, например «сброс … UTC / … МСК, осталось 1 ч 01 мин». Последние известные лимиты видны в `/status`. Документация OpenRouter также описывает суточный лимит запросов к бесплатным моделям, считаемый по UTC-дню ([страница лимитов](https://openrouter.ai/docs/api-reference/limits)).

**Повторы и ошибки.** Всего до 3 попыток при HTTP 408, 429, 5xx, сетевой ошибке, таймауте, пустом ответе и ошибке внутри ответа HTTP 200. При 429 пауза берётся из `Retry-After`, иначе из `X-RateLimit-Reset`, иначе 5·2ⁿ секунд. Если ждать нужно дольше 60 секунд (например, суточный лимит исчерпан), повтора нет. Ошибки 400, 401, 402, 403, 404 не повторяются, в журнале к ним добавлена подсказка (проверьте ключ, кредиты, название модели). После неудачи владелец получает «Не удалось распознать изображение, пришлите ещё раз», а в архиве остаётся запись со статусом «ошибка».

**Форматы картинок.** Бот принимает JPEG, PNG и WebP (формат определяется по первым байтам файла, а не по расширению; у PNG проверяются сигнатура, блок IHDR и ненулевые размеры). GIF OpenRouter принимает, но бот его отклоняет как «Формат не поддерживается». Размер ограничен `MAX_IMAGE_BYTES`.

## Архив 30 дней и хранение данных

Каждый результат сохраняется в архив: дата, заголовок (первые 8 слов), текст, путь к картинке, статус. Записи и файлы картинок старше `ARCHIVE_DAYS` (по умолчанию 30) дней удаляются при запуске и перед обработкой каждой новой картинки. Заодно чистятся выполненные записи входящей очереди и старые идентификаторы `mid`. В базе также лежат получатели, настройки (промпт, шаг мастера), marker опроса, журнал доставок и журнал запросов получателей. Для резервной копии достаточно копировать файл базы и папку с картинками при остановленном боте.

## Запуск как службы

> **Ни один из примеров ниже мной не запускался.** Пути и имена замените на свои, проверьте на тестовой машине.

### Linux: systemd

Файл `/etc/systemd/system/max-bot.service` (пользователь `maxbot` и каталог `/opt/max-bot` создайте заранее):

```ini
[Unit]
Description=MAX bot (long polling)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=maxbot
WorkingDirectory=/opt/max-bot
ExecStart=/opt/max-bot/.venv/bin/python /opt/max-bot/max_polling_bot.py
Restart=on-failure
RestartSec=10
TimeoutStopSec=40

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now max-bot
journalctl -u max-bot -f
```

`TimeoutStopSec=40` даёт боту время доработать задачи (до 30 секунд) после SIGTERM. Остановка по неверному токену (код 1) или ошибке настройки (код 2) при `Restart=on-failure` приведёт к бесконечным перезапускам: смотрите журнал и при необходимости добавьте `RestartPreventExitStatus=1 2`.

### Windows: планировщик заданий

Создайте задание на запуск при старте системы (PowerShell от администратора):

```powershell
$a = New-ScheduledTaskAction -Execute "C:\max-bot\.venv\Scripts\python.exe" `
     -Argument "C:\max-bot\max_polling_bot.py" -WorkingDirectory "C:\max-bot"
$t = New-ScheduledTaskTrigger -AtStartup
$s = New-ScheduledTaskSettingsSet -RestartCount 3 -RestartInterval (New-TimeSpan -Minutes 1) `
     -ExecutionTimeLimit ([TimeSpan]::Zero)
Register-ScheduledTask -TaskName "MaxBot" -Action $a -Trigger $t -Settings $s `
     -User "SYSTEM" -RunLevel Highest
Start-ScheduledTask -TaskName "MaxBot"
```

Особенности Windows: сигнал SIGTERM там недоступен, при остановке задания процесс завершается жёстко. Это безопасно для данных благодаря входящей очереди (необработанные события повторятся при запуске), но уже начатая рассылка может быть прервана. Логи бот пишет в стандартный вывод; для файла перенаправьте вывод в команде запуска или используйте утилиту-обёртку (например, NSSM; не проверялось).

## Long polling и webhook: когда переходить

| | Long polling (этот бот) | Webhook |
|---|---|---|
| Как приходят события | бот сам запрашивает `GET /updates` | MAX присылает POST на ваш HTTPS-адрес |
| Нужен публичный адрес и сертификат | нет | да |
| Подходит для | запуска дома, на ноутбуке, за NAT, для разработки и небольших нагрузок | постоянного сервиса с публичным адресом и растущей нагрузкой |
| Задержка | события приходят сразу, пока висит запрос | сразу |
| Состояние | нужно хранить marker (бот делает это в SQLite) | не нужно |
| Совместимость | работает только при **отсутствии** подписки webhook | активная подписка отключает long polling |

В документации MAX метод `GET /updates` помечен как не предназначенный для production-нагрузки (см. источники). Для небольшого бота с одним владельцем и десятком получателей это обычно не проблема. Стоит перейти на webhook, если: появились сотни получателей или высокая нагрузка; нужна гарантированная доставка событий без собственной очереди; бот живёт на сервере с публичным HTTPS-адресом; либо MAX потребует webhook для вашей категории бота. Оба режима одновременно работать не могут: подписка webhook отключает long polling, и наоборот, `DELETE /subscriptions` возвращает long polling.

## Безопасность

- Файл `.env` содержит токен и ключ. **Не коммитьте его**: добавьте `.env` в `.gitignore`, не отправляйте в чаты и не прикладывайте к заявкам. На Linux выставьте `chmod 600 .env`.
- В коде нет ни токена, ни ключа. Значения секретов и строки вида `Bearer …` и `sk-or-…` маскируются в каждой строке лога, включая трассировки ошибок; при старте в лог пишутся только последние две буквы значений. Логгеры `httpx` и `httpcore` приглушены, чтобы не светить адреса запросов.
- **Ключ из файла `limit_openrouter.py` в проект не переносился и нигде не повторяется.** Раз он побывал в переписке, отзовите его в OpenRouter (раздел Keys) и создайте новый, а новый впишите только в `.env`.
- Для ключа OpenRouter разумно задать лимит расходов в настройках ключа.
- Бот отвечает «Этот бот работает только по приглашению» всем посторонним (один раз на человека) и обрабатывает картинки только от владельца.
- Файлы базы и папка `incoming_images` содержат присланные картинки и тексты: ограничьте к ним доступ.

## Ограничения и нерешённые вопросы

1. **Формат OpenRouter.** Подтверждён руководством, но документация «Image Inputs» описывает Responses API; реальный запрос не выполнялся. Если `/chat/completions` с вашей моделью откажет, потребуется переход на `/responses`.
2. **Модель.** Неизвестно, поддерживает ли `nemotron-3.5-lightning:free` картинки. Бесплатные модели имеют суточные лимиты по запросам.
3. **Двойная рассылка после сбоя.** Если процесс упадёт посреди рассылки, при повторе обработки часть получателей может получить результат дважды.
4. **Параметр `types`.** Документация MAX не показывает, как передавать список; бот передаёт повторяющимся параметром (`types=a&types=b`), как Go-клиент MAX. Если события не приходят, это первое, что стоит проверить.
5. **«Не запустил бота».** Отказ 4xx (кроме 429) при отправке бот трактует так, если от получателя не было Start или сообщения. Это вывод, а не подтверждённый факт: причину смотрите в логе.
6. **Лимит 2 сообщения в секунду** в чат — правило самого бота; в документации MAX указан только код 429.
7. **`GET /updates` не для production** по документации MAX; предельную нагрузку не измеряли.
8. **GIF** не принимается ботом, хотя OpenRouter его поддерживает.
9. **Один владелец.** Команды и обработка картинок доступны одному `OWNER_ID`.
10. **Сроки жизни ссылок на картинки.** Если ссылка на файл в MAX истечёт до скачивания, бот сообщит «Не удалось получить файл, пришлите ещё раз».
